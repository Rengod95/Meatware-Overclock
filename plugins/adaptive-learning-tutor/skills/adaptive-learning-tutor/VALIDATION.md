## 추가 확인의 범위

전체 패키지를 임시 홈·프로젝트·사용자 지정 폴더에 복사했다. Codex·Claude Code·Gemini CLI·Pi에 대해 설치 경로를 선택하고 복사본의 구조 검사를 실행했다. Pi와 Codex의 공유 경로에서는 같은 사본을 재설치하지 않는지 확인했다. 이는 실제 에이전트 프로세스의 스킬 발견·활성화 시험이 아니라 **공식 문서에 근거한 로컬 경로·복사 로직 시험**이다.

미리보기에서 쓰기가 없고, 내용이 다른 기존 설치는 그대로 보존되는지 확인했다. 가상의 별도 학습 저장소에서 동의 없는 초기화 거부, 명시적 초기화, 기본 no-write 저장 검토, apply에 의한 revision 증가, 오래된 revision의 저장 거부를 확인했다. 이 기록은 실제 사용자의 개인 학습 저장소나 실제 동의를 생성한 것이 아니다. 임시 폴더는 시험 후 제거했다.

제작 계약 템플릿은 lint에서 통과하고 produce에서 예상대로 거부되었다. 템플릿은 `example:true`이며 실제 학습 제작을 승인하지 않는다. 패키지의 SKILL frontmatter와 Codex 메타데이터를 PyYAML로 독립 구문 분석했고, 두 JSON Schema와 기본 예시를 jsonschema의 Draft 2020-12 검사기로 확인했다. 두 라이브러리는 검증 환경에서만 사용했으며 배포 도구의 의존성은 아니다.

## 파일 무결성과 재현

배포 폴더의 `SHA256SUMS`는 그 파일 자체와 Python 캐시를 제외한 파일 해시 목록이다. 아래 명령은 파일 내용과 인벤토리가 일치하는지 확인한다. 해시는 악의적 변경의 인증·전자서명·설명의 진실성을 대신하지 않는다.

```bash
python3 scripts/validate_package.py --integrity
python3 -m unittest discover -s tests -v
python3 scripts/build_standalone.py
```

독립형 프롬프트는 핵심·관련 참조·설정에서 생성되며 동기 검사를 통과했다. 내용 수정 뒤에는 독립 프롬프트 재생성과 검사가 필요하며 기존 배포 해시와 달라지는 것은 정상이다. 원본 아카이브의 해시는 docs/source-manifest.json에 별도로 보존했다.

## 수행하지 않은 검증

Codex·Claude Code·Gemini CLI·Pi 실행 파일은 이 환경에서 발견되지 않았다. 실제 호스트 모델 호출·암시적 활성화·스킬 목록 반영·CLI 또는 IDE의 종단 간 대화 시험은 하지 않았다. 공식 스펙 형식과 설치 경로를 지원한다는 사실을 호스트의 실행 인증으로 표현하지 않는다.

[행동 사례 26개](evals/cases.json)는 **설계만 완료**했다. 이를 모델에 실행해 통과 판정을 내리지 않았다. 위의 추가 확인 26개와는 다른 자료다. 설명의 교육적 품질, 실제 사용자 이해, 독립 적용, 장기 기억·전이는 측정하지 않았다. 자체 작성 예시를 실제 사용자 응답으로 취급하지 않았다.

기존 개인 상태의 마이그레이션, 원본 두 상태의 자동 병합, 사용자 장치 설치, 클라우드 동기화, 예약·백그라운드 프로세스는 수행하지 않았다. 새 구조 검사기는 선언한 YAML/JSON Schema 부분집합과 필드 관계를 검사할 뿐, 승인자의 신원·출처의 진실성·설명의 의미를 증명하지 않는다.
