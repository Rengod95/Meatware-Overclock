# 장르·전개·표상·매체

장르는 글이 하는 일, 전개는 논리의 순서, 표상은 표현 수단, 매체는 전달 형식이다. PDF라는 이유로 설명문이 되지 않으며, 읽기 중심이라는 이유로 모든 문서를 강의체로 바꾸지 않는다.

| 역할/장르 | 중심 의무 | 주의 |
|---|---|---|
| 개념 설명·심화 학습문 | 구분·필요·관계·전제·한계를 설명 | 정의의 목록, 불필요한 행정 표찰 금지 |
| 분야 안내 | 질문·대상·관점·용어·탐구 방향을 연결 | 일정·직무 목표를 강제하지 않음 |
| 완성 사례 해설 | 단서·조건·중간 과정·결과를 추적 | 운영 결과와 가상 예시 구분 |
| 튜토리얼 | 실제 수행 순서·성공 조건을 안내 | 읽기 요청에 실습 의무를 붙이지 않음 |
| 방법 안내 | 목표 작업의 전제·절차·확인 | 개념 교재 전체로 확장하지 않음 |
| 운영 절차 | 권한·위험·중단·복구 조건 | 자연스러운 산문을 위해 경고를 숨기지 않음 |
| 참조 | 정확한 값·API·용어·버전의 조회 | 이유를 배우는 요청에 목록만 주지 않음 |
| 명세 | 검증 가능한 의무·조건·예외 | 쉬운 표현으로 의무를 약하게 바꾸지 않음 |
| 요구사항 | 상황·행위자·결과·제약·수용 조건 | 제안과 채택을 구분 |
| 아키텍처 | 경계·책임·흐름·제약 | 계획을 실제 운영 사실로 바꾸지 않음 |
| 설계 제안 | 문제·대안·근거·남은 결정 | 승인된 설계처럼 표시하지 않음 |
| 결정 기록 | 당시 맥락·선택·대안·영향·재검토 | 기록 없는 작성자의 생각을 발명하지 않음 |
| 코드 walkthrough | 실제 입력·분기·상태·계약 | 전 줄 주석이나 문법 나열에 머물지 않음 |
| 문제 해결 가이드 | 증상·후보·구별 증거·조치 | 단일 원인 확정 금지 |
| 사건 복기 | 시간·영향·확인 근거·기여 조건 | 교훈용으로 실제 사실을 바꾸지 않음 |
| 이전 안내 | 차이·의존성·절차·되돌림·검증 | 미실행 이전을 완료라고 하지 않음 |
| 변경 안내 | 실제 변경·영향·할 일 | 의도된 기능을 완료 기능으로 쓰지 않음 |
| 조사·비교 분석 | 질문·선정 기준·근거·대안·한계 | 출처 없는 승자·점수·표준화 주장 금지 |

학습용 해설을 붙이더라도 업무용 원문의 장르 계약은 보존한다. 필요하면 원문과 해설을 나누고 대응 위치를 제공한다. 서로 다른 목적·수명·독자 경로가 있을 때만 별도 파일을 만든다. 모든 장르를 학습 상태의 새 enum으로 저장하지 않는다. state.md의 기존 저장 장르 중 의미가 맞는 것을 쓰고 차이를 제목·설명으로 남긴다.
