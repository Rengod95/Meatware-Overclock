# 맥락 수집과 근거 기반 진단

## 수집 원칙: 넓게 검토하고, 선택적으로 묻는다

이 절차의 목적은 많은 정보를 모았다고 주장하는 것이 아니라, 자료 설계를 바꿀 맥락을 놓치지 않는 것이다.
각 축을 확인하되 관계없는 정보는 '비적용'으로 둔다. 사용자의 실제 질문·기존 반응·권한 있는 자료를
우선 읽고, 같은 내용을 다시 질문하지 않는다. 시간이 없다는 이유로 배경지식을 상상하거나,
맥락을 많이 모은다는 이유로 개인의 민감한 정보까지 수집하지 않는다.

|맥락 축|확인할 내용|설계에 미치는 영향|
|---|---|---|
|요청의 계기|새 분야 탐색, 업무 산출물 이해, 특정 문장 막힘, 장기 재학습|진입점과 먼저 만들 자료|
|목표와 책임|당장 이해할 관계, 중기 판단, 장기 유지·관리·탐구 범위|깊이·기초 경로·전이 사례|
|도메인과 경계|분야, 하위 시스템, 버전, 주변 분야, 의도적 유예|어떤 선수 지식을 지금 펼칠지|
|대상 자료|실제 코드·문서·로그·설계안·기존 교재와 출처 위치|명세와 설명, 실제 구현의 일치|
|이미 관찰된 지식|자신이 쓴 설명, 사용자 질문, 검토 수정, 도움 수준|반복을 줄일 관계와 보충할 관계|
|현재 막힘|마지막 이해 지점, 최초 불명확 지점, 스스로 추측한 규칙|경쟁 원인 후보와 복구 방식|
|언어와 표상|한국어·전문용어·수식·코드·도표 해독 경험|용어 계약과 표상 다리|
|선호와 자원|읽기 모드, 선호 문체, 매체, 한 번 읽을 분량|자료 분할과 선택 심화|
|동기와 지속성|왜 배우는지, 자율성, 반복 가능한 학습 여건|단기 문제와 장기 경로의 균형|
|위험과 검증|잘못 이해했을 때 결과, 실제 운영/보안/규정 관련 여부|출처 수준과 출고 차단 기준|
|지식의 역사|이전 자료, 교정된 오해, 최근 다루지 않은 관계|적절한 상기·재연결·후속 사례|
|권한과 보관|검색 범위, 코드 실행 여부, 저장 위치와 사용자 동의|도구 사용 및 기록 정책|

각 항목은 상태(observed/user_reported/assumed/unknown/conflicting/not_applicable),
출처, 확인 시점, 영향을 받는 결정, 차단 여부를 가진다. 화면에 다 보여 줄 필요는 없다.
선호는 실제 사용자 발언에서 알 수 있어도 도메인 지식은 별도로 미확인일 수 있다.

## 검색·질문의 순서

대화에 이미 제공된 내용→권한 있는 관련 파일·연결 자료→현재 사실이 필요한 공식 원문→
남은 중요한 차이를 가르는 사용자 질문의 순서로 접근한다. 자료가 없는 경우 없다고 기록한다.
파일 제목·이전 링크만으로 내용을 읽었다고 하지 않는다. 연결 서비스는 해당 커넥터의 읽기 기능을
사용하고, 범위를 넘어 이메일·캘린더 등을 뒤지지 않는다.

질문을 선택할 때는 어느 설계 선택이 달라지는지, 틀린 가정의 손실은 큰지, 다른 자료로 대신 확인할
수 있는지, 응답 부담은 얼마인지를 고려한다. 이를 가짜 수치나 '최적 6문항' 규칙으로 만들지 않는다.
기존 지식의 세부 확인을 거부해도 완성 설명을 받을 수 있다. 이때 출발점은 잠정 가정이다.

## 학습자 모델의 단위

개념 자체보다 관계에 관한 주장을 기록한다. 예: '호출이 끝난 시점과 요청한 작업이 완료된 시점을 구분한다.'
주장마다 관찰 증거, 제공된 도움, 표상, 맥락, 시점, 가능한 다른 해석을 연결한다.

노출(exposure)과 지식 상태는 따로다. 자료 생성은 노출도 아니며, 사용자에게 전달했다고 실제로 읽었음을
확인한 것도 아니다. 해설을 읽었다고 보고한 것은 observed-independent로 자동 승격하지 않는다.

상태는 대화의 서술에서는 미확인·자기보고·도움 조건·맥락별 지지를 구분한다.
영속 JSON에는 이 표현을 새 enum으로 쓰지 말고 state.md의 기존 스키마 label과 assistance를 사용한다. 이는 직선 단계나 심리측정 점수가 아니다.
문서참조 도움, 힌트 도움, 정답 노출은 assistance에 별도로 남긴다. 문서를 보면서 판단하는 능력도
그 조건에 맞는 가치가 있지만 무도움으로 바꿔 적지 않는다.

아니라 '이 자료에서 대비할 수 있는 혼동'으로만 사용한다.

## 진단 한 회의 작업

확인할 관계를 고르고, 가능한 지식 상태들이 다른 응답을 만들 사례를 고른다. 사용자가 허용한 경우에만
해설 전 구분·예측을 받는다. 이후 같은 내용의 표현을 바꾸거나 중간 상태를 추가해 도움이 되는지 본다.
모든 요소를 동시에 바꾸면 원인을 구분하기 어렵다는 점을 기록한다. 교정 후 답변은 교정 전 지식의
증거가 아니다. 단일 답변을 일반 숙달로 해석하지 않는다.

반응의 이유에는 질문 자체의 모호성도 포함한다. 맞힌 정답이 암기였을 수 있고, 틀린 결과가 계산·표기
오류였을 수 있다. 지적 능력, 장애, 성격, 교육 수준을 추정하지 않는다. '설명이 안 된다'는 이유로
깊은 직관이라고 칭찬하거나 무지라고 단정하지 않는다.

## 언제 진단을 멈추는가

추가 응답이 설명 깊이·장르·기초 보충·예시·읽기 순서를 바꾸지 않거나 사용자의 응답 예산을 넘으면
진단을 멈춘다. 중대한 사실·권한의 공백은 차단으로 남기고, 지식 미확인은 안전한 가정과 선택적
보충으로 다룬다. 미확인 때문에 모든 자료 생성을 무기한 중단하지 않는다.

이 후보 목록은 원본 Orchestrator에서 통합한 설계 정책이며 표준화된 검사나 검증된 학습자 유형이 아니다. 출처와 변경 범위는 docs/PROVENANCE.md에 있다.
