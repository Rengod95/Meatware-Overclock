# 산출물과 문제에서 출발하는 학습

## 업무 인계

원본 파일/절/심볼과 버전, 실제 완료 범위, 확인 근거, 결정과 대안, 미확인, 학습 후보를 받는다. `assets/work-handoff.template.json`은 코드뿐 아니라 문서·개념·아키텍처·프로젝트 파운데이션에 사용할 수 있다. tests 대신 verification에 실행·문서 대조·논거 검토 등의 실제 유형을 남긴다.

인계문은 증거를 찾아갈 단서이지 최종 진실이 아니다. 실제 소스에 대조하고 기록된 의도, 관찰한 동작, 실행 결과, 제안, 교육적 재구성을 분리한다. 이유가 없으면 당시 작성자의 의사결정을 발명하지 않는다. 잘못되거나 과도한 원본을 학습자의 이해 부족으로 정당화하지 않는다.

## 해설

코드는 대표 입력과 중간 상태를, 요구사항은 상황·권한·상태·검증을, 개념 모델은 동일성과 구분·변화를, 아키텍처는 경계·제약·실패·대안을, 파운데이션은 변경 이유·의존·계약·강제 장치를 설명한다. 폴더 이름이나 패턴 용어만 읽어 주지 않는다.

핵심 원리를 설명한 뒤 실제 원본의 문장·분기·선택으로 돌아와 조건을 바꾸면 무엇을 다시 확인해야 하는지 연결한다. 이 규칙은 후학습 분기에만 적용하며 독립적인 개념 탐구에 파일을 요구하지 않는다. 실제 구현과 문서 제안이 다른지 확인한다. 교육용 예제는 별도이며 생략·미실행·가정·안전 한계를 밝힌다.

## 디버깅에서 배우기

증상, 기대 동작, 관찰된 사실, 원인 후보, 후보를 가르는 가장 유용한 안전한 관찰, 조치, 결과를 분리한다. 상태 코드 하나·상관 하나로 원인을 확정하지 않는다. 조치 후 사라진 증상은 원인 증명과 다르다. 여러 기여 조건을 단일 원인 이야기로 줄이지 않는다.

해결이 급하면 사용자의 우선순위를 따른다. 전체 배경 교과서를 먼저 요구하지 않는다. 가설의 범위를 밝힌 채 일반적인 개념 설명은 제공할 수 있다. 실제 사건의 원인은 증거가 있는 범위에서만 설명한다. 로그의 비밀·개인정보는 최소 수집하고 실제 실행은 권한을 따른다.

완화, 복구, 근본 수정, 근본 원인 검증을 구분한다. 다음 독립 심화 요청에서는 원래 사건으로 되돌리지 않고 지금 관심사를 따라간다.
