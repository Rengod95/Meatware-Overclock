# 호출 예시

아래 문장은 시험용 요청이다. 현재 사용자의 실제 동의나 지식 기록이 아니다. 각 호스트의 명시 호출 뒤에 이어 붙일 수 있다.

## 개념과 응용

빌더 패턴의 의도와 구현 표현을 구분해서 설명해 줘. 첨부한 패키지에 응용할 여지가 있는지도 검토하되, 굳이 적용하지 않는 편이 나은 조건도 알려 줘. 코드는 수정하지 마.

## 독립 딥다이브

DDD의 엔티티 개념을 현재 프로젝트와 연결하지 말고 깊이 알고 싶어. 단순히 식별자가 있다는 설명을 넘어, 동일성을 어떤 맥락에서 유지하는지와 구분이 불필요한 경우를 연결해서 설명해 줘. 이번 한 편은 제작안 없이 바로 작성해 줘.

## 낯선 분야 입문

물류 산업을 거의 몰라. 주요 대상과 흐름, 용어, 반복되는 문제와 판단 관점을 먼저 잡고 싶어. 용어의 표준·관행 차이는 근거를 확인해 줘. 전체 교재나 주차별 계획 대신 방향을 잡는 안내문을 만들어 줘.

## 문제에서 시작

첨부한 오류 로그를 보고 우선 가능한 해결책을 정리해 줘. 이후 확인된 원인과 가설을 구분하면서 관련 개념을 읽기형으로 설명해 줘. 실제 서비스에는 명령을 실행하지 마.

## 산출물 후학습

이 아키텍처 문서의 주요 결정 하나를 골라 전제와 대안부터 설명해 줘. 실제 기록된 이유와 교육용 재구성을 구분하고, 조건이 바뀌면 원본에서 무엇을 재검토할지 연결해 줘.

## 국소 복구

앞의 설명에서 '같은 형태와 같은 의도는 다르다'는 연결만 잘 모르겠어. 같은 예시로 세 문단 정도만 보충해 줘. 전체 설명은 다시 시작하지 마.
