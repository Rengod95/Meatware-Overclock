# 통합 설계와 원본별 처리

## 이 패키지가 통합한 것

| 원천 | 가져온 책임 | 이번 조정 |
|---|---|---|
| Learning Design Orchestrator | 폭넓고 선택적인 맥락 수집, 17개 경쟁 원인, 파트 연결, 제작 확인, 근거가 남는 검수 | 산출물 필수 전제 제거; 승인 정책 분리; 작은 요청에 작은 설계 |
| Sustainable Learning Tutor | 읽기형 해설, 국소 복구, 기초·사례 누적, 실제 지식 증거 구분, 선택적 로컬 저장 | 비업무·일회성 탐구를 동등하게 수용; 초기 목표·개인 증거 제거 |
| 사용자의 진입점 확장 요구 | 개념·심화·도메인 입문·문제·후학습의 공존, 분량과 깊이 분리 | routing과 행동 평가의 주축으로 승격 |
| 이번 패키징 | 표준 SKILL.md, 호스트 설치 도구, 메타데이터, 자체 검사, 독립형 생성 | 특정 모델·경로·서버에 학습 핵심을 종속시키지 않음 |

원본 SKILL.md 두 개를 동시에 활성화하지 않는다. 하나의 핵심 지침이 승인·쓰기·기록의 우선순위를 정한다. 필요한 전문 도메인/아티팩트 제작 스킬과는 역할을 나눌 수 있지만 그 호스트의 안전·권한은 바꾸지 않는다.

## 버전과 상태의 소유권

패키지/제작 계약은 0.3.0이다. 학습 상태 JSON은 원본 Tutor 0.1.0 형식을 유지한다. 두 버전은 목적이 다르다. 기존 Tutor의 스키마와 검증/저장 로직, 35개 합성 테스트를 보존하고 신규 패키지에서 다시 실행한다.

초기 상태는 사용자 지식·응답·과거 승인·도메인이 비어 있다. 선호는 제안 기본값이며 원본 템플릿의 과거 대화 출처를 복제하지 않았다. 기존 상태를 새 기본값으로 덮어쓰지 않는다. 실제 사용 중인 상태를 그대로 시험·이전한 것은 아니다.

Orchestrator의 프로젝트 상태와 Tutor 상태를 단순 연결·자동 변환하지 않는다. 기존 학습 증거를 옮기려면 실제 원본, 작성자, 도움 조건, 맥락, 사용자 동의를 확인하고 수동으로 해당 스키마에 대응해야 한다. 기존 '무도움/전이' 표현을 하나의 지지 label로 압축해 증거를 잃지 않는다.

제작안·승인·검수는 `assets/lesson-contract.schema.json`의 별도 계약으로 저장한다. `check_contract.py`는 범위·승인 해시·파일 해시·검수 필드를 확인한다. 학습자 상태에는 이 내용을 새 루트 필드로 끼워 넣지 않는다.

## 정책 결정

이번 통합본의 기본값은 `preview`다. 이전 대화의 제작 전 확인 선호를 새 에이전트에서도 보존한다. `adaptive`는 단일 요청은 바로 설명하고 큰 묶음만 확인하는 선택 가능한 정책이다. 실제로 그 정책을 요청한 경우에만 변경하며 설치 자체를 선호 철회로 취급하지 않는다.

입력 해석과 설명 품질은 모델 지침이다. 코드 검사기가 자연어 질문의 깊이·적절한 사례·실제 동의를 자동 판정하지 않는다. 예를 들어 사람이 JSON에 single을 잘못 적으면 검사기만으로 실제 요청이 여러 편인지 알 수 없다. 실제 요청과 대조하는 책임이 남는다.

## 포함하지 않은 것

원본 연구 보관본 전체, 오래된 비교용 장문, 실제 개인 학습 상태, 서로 충돌하는 원본 진입점, 자동 모델 실행·API 연동·예약 복습·감시·웹훅 서버는 포함하지 않았다. 과거에 제시된 생성물 파일은 현재 런타임에서 찾지 못했으므로 바이트 단위 병합했다고 주장하지 않는다. 해당 대화에서 확정된 설계 요구를 현재 원본과 결합했다.
